# tene Report

Author and revise the report in the user's current conversation language, following the workflow language contract.

Require the `report` phase. Generate the report, then complete authored sections instead of treating the generated summary as sufficient.

Include predecessor Sprint continuity, every changed file and implemented behavior, the intent each processing change fulfills, all Understanding Layers, the Six Questions for important components, QA verdict and evidence, operational impact, user policy decisions, deferred items with reasons and target Sprint, and retrospective lessons.

Validate the report and dry-run archive. Do not archive if evidence is stale, a blocker remains, or required human approval is absent. Read [workflow](../../references/workflow.md).
